## 2. 总体架构：分层双进程

```
┌──────────────────────────────────────────────────────────────┐
│  Electron 网关层（主程序）                                    │
│  ┌────────────────────────────────────────────────────────┐  │
│  │  Main Process（主进程，Node 环境）                      │  │
│  │  ┌──────────┐ ┌─────────┐ ┌──────────┐ ┌────────────┐ │  │
│  │  │ 内核管理  │ │ 任务调度 │ │ 授权/支付 │ │ 进程守护    │ │  │
│  │  │(child_   │ │ (4路并发 │ │ (在线校验 │ │ (拉起/心跳/ │ │  │
│  │  │ process) │ │  +取消)  │ │  +扫码)   │ │  重启)     │ │  │
│  │  └──────────┘ └─────────┘ └──────────┘ └────────────┘ │  │
│  │  本地 HTTP 客户端 / 事件轮询器 / 工作区管理器 / LLM 配置    │  │
│  └──────────────────────────┬─────────────────────────────┘  │
│  ┌──────────────────────────▼─────────────────────────────┐  │
│  │  Renderer（渲染进程，React + shadcn/ui）                │  │
│  │  纯 UI：仅通过 preload 暴露的白名单 API 与主进程通信      │  │
│  │  【D19 铁律：渲染进程零 Agent/LLM/编译业务逻辑】          │  │
│  └────────────────────────────────────────────────────────┘  │
└──────────────────────┬───────────────────────────────────────┘
                       │ 本地 HTTP（127.0.0.1:随机端口 + Token）
┌──────────────────────▼───────────────────────────────────────┐
│  Agent 后台内核（独立进程，Nuitka 编译，无窗口）               │
│  FastAPI(仅本地) + LangGraph(checkpoint) + RAG + 编译工具      │
│  任务执行器：线程池 4 路并发                                   │
│  SQLite: tasks.db（任务+事件+断点+工作区）                    │
└──────────────────────┬───────────────────────────────────────┘
                       │ HTTPS（公网，仅服务端相关请求）
┌──────────────────────▼───────────────────────────────────────┐
│  轻量服务端（本地先行可迁云，D24）                             │
│  聚合支付订单 / 订阅签发 / 在线校验 / 机器码管理 / 更新发布     │
└──────────────────────────────────────────────────────────────┘
```

**D19 铁律（架构红线）**：Agent/LLM/编译逻辑**只存在于后台内核进程**；Electron **渲染进程零业务逻辑**，只通过 preload 白名单 API 与主进程通信。Electron 安全默认开启（`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`）。

**进程模型**：
- Electron 主进程启动 → 拉起内核子进程（`child_process.spawn`）→ 健康检查握手 → 就绪
- 内核：无窗口进程，随机端口，启动 Token 鉴权
- 退出 → 优雅停内核；内核崩溃 → 主进程心跳检测自动重启（≤10s）

## 4. Electron 网关层设计

### 4.1 模块结构

```
src/
├── main/                     # 主进程（Node）
│   ├── index.ts              # 入口、窗口、生命周期
│   ├── kernel.ts             # 内核子进程管理（拉起/健康检查/崩溃重启）
│   ├── auth.ts               # 订阅校验（在线校验调用、本地缓存、7 天试用）
│   ├── payment.ts            # 扫码支付（创建订单/轮询/回调处理）
│   ├── ipc_client.ts         # 本地 HTTP 客户端（调用内核）
│   ├── updater.ts            # 检查更新（D14 阶段 2 手动）
│   └── store.ts              # electron-store + safeStorage
├── preload/
│   └── index.ts              # contextBridge 白名单 API（严格最小化）
└── renderer/                 # React + TS + shadcn/ui
    ├── pages/                # 主界面/任务详情/工作区/设置/订阅
    ├── components/
    └── stores/
```

### 4.2 界面设计

1. **主界面**：需求输入 + 提交 + 任务列表（4 路并发槽位展示）
2. **任务详情**：流程状态图、实时日志流（虚拟滚动）、重试次数、产物/工作区入口、"从头重跑"按钮
3. **工作区（D11）**：工程列表 + "继续优化"（指定 workspace 提交迭代需求）
4. **设置**：LLM 配置、内核状态、知识库状态、**检查更新**
5. **订阅页**：价格展示（**标准 ¥59/半年，内测优惠 ¥29/半年**）+ 扫码支付 + 试用倒计时 + 优惠倒计时

### 4.2.1 工程源码浏览器（V1.5 补充，类 Cursor/Qoder 体验）

- **目标**：应用内直接查看生成的固件工程源码，不必跳出到系统资源管理器
- **W2 基础版（只读）**：
  - 工程文件树（`outputs/{task_id}/` 或工作区目录），按 ESP-IDF 工程结构展示（main/、CMakeLists.txt、sdkconfig、build/ 产物）
  - 点击文件 → 语法高亮查看（main.c、CMakeLists.txt、sdkconfig）
  - "在系统资源管理器中打开"、"导出 zip"入口
- **W3 增强版（可编辑闭环）**：
  - 内置简单编辑器（修改 main.c 后保存 → 一键重新编译 → 查看新日志）
  - 与工作区迭代打通：改完文件可直接"继续优化"或重编译
- 依赖内核：`GET /api/workspace_files?path=`（文件树）+ `GET /api/workspace_file?path=`（文件内容，防目录穿越）+ `POST /api/workspace_file`（保存，W3）

### 4.2.2 会话/聊天记录（V1.5 补充）

- **目标**：像聊天工具一样回看"之前让 Agent 做过什么、结果如何"，并可从旧会话继续
- **W2 基础版（会话视图）**：
  - 任务历史升级为会话卡片：需求（用户）→ 关键事件/结果（Agent），按时间倒序
  - 每条会话展示：需求原文、芯片选型、编译结果、产物入口、Token 用量
  - 支持从会话卡片直接"继续优化"（跳转工作区迭代）
- **W3 增强版（多轮对话链）**：
  - 同一工作区的迭代需求串成对话链（需求1 → 结果1 → 需求2 → 结果2…），完整追溯
  - 支持在旧会话上追加新需求（多轮对话式交互）
- 依赖内核：`GET /api/conversations`（会话列表）+ `GET /api/conversation?task_id=`（单会话详情，含事件与结果）；会话链由 workspaces.history 扩展

### 4.3 任务调度

- 并发（默认 2，可调 1~4，S4）：内核线程池；网关维护队列（PENDING → 空闲槽位分配）
- 取消：POST cancel → 节点安全退出 → CANCELED
- 断点：默认节点级续跑（checkpointer）；"从头重跑"= 任务级

## 5. Agent 后台内核层设计

### 5.1 阶段 1 代码改造

| 文件 | 改动 |
|---|---|
| `api/main.py` | Token 鉴权、取消/事件/续跑/工作区接口、端口参数化、日志落盘 |

### 5.2 内核 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查（版本、并发槽位） |
| POST | `/api/run_task` | 提交任务（支持 `workspace_id` 工作区迭代） |
| POST | `/api/cancel_task` | 取消（幂等） |
| GET | `/api/get_result?task_id=` | 查询结果 |
| GET | `/api/events?task_id=&after_seq=` | 增量事件（500ms 轮询） |
| POST | `/api/resume_task` | 断点续跑（默认节点级；`full_restart=true` 任务级） |
| POST | `/api/shutdown` | 优雅退出 |
| GET | `/api/export?task_id=` | 导出工程 zip / bin |
| POST | `/api/config` | 热更新 LLM 配置 |

请求头携带 `X-Kernel-Token`。

### 5.3 工作区（D11）

- `workspaces/` 为持久工作目录，工程可反复迭代
- 工作区表：`workspace_id / project_dir / chip / created_at / last_updated / history`
- 提交新需求指定 `workspace_id` → Agent 读取现有工程作为上下文 → 增量优化 → 重编译

### 5.4 事件粒度设计（V1.4 补充：明确"能看到操作过程"）

事件分 **4 级粒度**，全部入库供 UI 实时展示（解决"只看到 3 行、看不到操作过程"）：

| 级别 | 示例 | 说明 |
|---|---|---|
| L1 任务级 | 任务已提交 / 任务完成 / 任务失败 | 已实现（W1） |
| L2 节点级 | 进入 chip_select / 进入 rag_search / 进入 code_generate / 进入 compile_build / 进入 error_fix | **W2 实现**（node 开始/结束 + 耗时） |
| L3 动作级（操作文件过程） | 复制工程模板到 outputs/{id} / 正在写 main.c / 写入完成 / 保存 README / 启动 idf.py build | **W2 实现**（节点内的关键动作，含文件名） |
| L4 进度级 | 编译进度 30% / 已生成 bootloader.bin / 已生成 esp32s3_app.bin | W2 实现（compile_tool 进度回调） |

配套：节点开始/结束各一条事件（含耗时），前端可用时间轴/步骤条展示流程状态图（阶段2文档 4.2 任务详情）。

### 5.5 Token 用量统计与优化（V1.4 补充）

**目标**：可查询"任务是否合理跑完"+"token 消耗是否合理"，并支撑后续优化。

- **记录**（W2 实现）：`LLMAdapter.chat()` 返回的 usage（prompt_tokens / completion_tokens）写入新表 `task_llm_usage(task_id, node, model, prompt_tokens, completion_tokens, cost, ts)`；每任务汇总展示在任务详情（总 token、按节点分布、估算费用）
- **查询**：任务详情页展示"LLM 用量"区块；`/api/get_result` 返回 usage 汇总
- **优化空间**（阶段 2 完成后做，见结论）：
  1. RAG 注入量压缩（top_k 调优、按相关性截断、去重）
  2. Prompt 精简（system 提示压缩、模板复用）
  3. 修复循环去重（fix_history 已部分实现）
  4. 长输出截断/续写策略
- **结论**：**统计 W2 就做**（成本低、需要从第一版建立基线数据）；**优化动作等阶段 2 完成后**（优化需要统计数据支撑，且不阻塞功能交付）

## 6. IPC 契约与事件机制

1. **传输**：本地 HTTP（127.0.0.1 + 随机端口），浏览器 Network 可直接调试（路线规划要求）
2. **鉴权**：启动 Token（主进程生成 → 命令行传参 → 请求头带回）
3. **事件流**：内核写 SQLite 事件表 → 主进程 500ms 增量轮询 → IPC 推给渲染进程 → 前端实时渲染
4. **取消**：节点内检查取消标志，安全退出
5. **断点**：checkpointer 按 `thread_id=task_id` 存全状态

## 7. 核心功能流程设计

### 7.1 启动流程

```
双击 L-CODE
→ 授权检查（未开通 → 订阅页：试用/扫码）
→ 主进程拉起内核（--port --token）
→ /api/health 就绪（≤15s）→ 主界面
→ 每 10s 心跳；在线校验按策略（启动/定时）与服务端对时
```

### 7.2 扫码支付开通（D18/D21B）

```
订阅页 → 主进程请求服务端创建订单（聚合支付平台）
→ 返回支付二维码（支付宝/微信，聚合平台生成）
→ 用户扫码付款 → 聚合平台回调服务端 → 服务端签发订阅（绑定机器码）
→ 客户端轮询订单状态 → 拉取订阅写入本地 → 解锁
→ 到期前 7 天提示续费
```

### 7.3 任务提交与并发（N=4）

```
GUI 输入需求 → 提交（可选绑定工作区）
→ 网关入队 → 空闲槽位 → 内核线程池执行
→ 节点事件实时推送 → SUCCESS/FAILED → 导出/继续优化
```

### 7.4 中断/断点/崩溃恢复

```
停止 → cancel → 节点安全退出 → CANCELED（checkpoint 已存）
继续 → resume_task（节点级默认）或"从头重跑"
内核崩溃 → 心跳失败 → 自动重启 → RUNNING 置 INTERRUPTED → 提示续跑
```

### 7.5 任务结果与产物 UX（V1.4 补充：产物可见性）

- **收尾事件**：任务完成时最后一条事件为 **"产物就绪"**，附产物路径与文件列表（`build/esp32s3_app.bin` 等），不得在产物落盘前发"任务完成"
- **运行中**：任务状态显示当前阶段（L2 节点），编译阶段显示"正在生成产物…"，避免用户误以为卡死
- **完成后**：任务详情展示产物路径 + "打开文件夹" / "导出" 入口（阶段2文档 4.2 产物入口）
- **异常时**：产物缺失（如编译通过但 bin 未落盘）给出明确错误提示，而非静默

## 8. 服务端、支付、授权与防破解设计

### 8.1 服务端设计（D4 定稿；D24 本地部署先行，可迁云）

**职责**：
1. 聚合支付订单创建/回调确认（D21B）
2. 订阅签发（绑定机器码、半年有效期）
3. **在线校验**接口（客户端启动/定时调用：`此机器此订阅是否有效`）——D3 最难破解方案
4. 机器码管理（换机迁移、吊销、风控）
5. 可选：版本更新发布、用量统计

**部署策略（D24/S3 定稿）**：
```
阶段 2 初期：本地搭建（Docker Compose）+ Cloudflare Tunnel 公网暴露（免费，无需公网 IP）
   → 在线校验走 Tunnel 域名，用户端可正常访问
业务增长后：整体迁移云服务器（轻量云 ¥50/月级，Docker 无缝迁移，Tunnel 可撤）
```
> ⚠️ 关键约束：**在线校验要求用户端能访问服务端**。Cloudflare Tunnel 解决公网可达；服务端不可达时客户端按离线缓存宽限（D3 弱化但可用）。

**技术形态（S1A 定稿）**：Go 单二进制 + SQLite + Docker Compose；支付平台按 S2 试用后选定。

### 8.2 授权模型

- 商品（S5 定价策略）：
  - **标准价：半年 ¥59**（正式版基准）
  - **内测/抢先体验优惠：半年 ¥29**（限时；收集一批真实付费开发者反馈、验证产品价值后，取消优惠恢复标准价）
- 试用：**7 天限时**（D5B）
- 授权：`{product: L-CODE, plan: half-year, price_tier: standard|early, start, expire, machine_id}`
- 校验：在线为主（启动+定时，走 Cloudflare Tunnel）；离线缓存容错

### 8.3 防破解层次

1. Nuitka 编译内核（无源码）
2. **在线校验**（最难破解）+ 启动 Token + 随机端口
3. 授权逻辑在主进程，内核不含授权
4. 聚合平台订单签名校验（防伪造支付回调）

## 9. 打包与分发

### 9.1 内核打包（D10 定稿）

```
Nuitka --standalone 输出 dist 目录 → Inno Setup 封装安装包（不 onefile、不分发裸 dist）
三平台：Windows(NSIS) / macOS(dmg) / Linux(AppImage 或 tar.gz)
```

### 9.2 网关打包（Electron，D20）

- **electron-builder**：Windows NSIS / macOS dmg / Linux AppImage
- asar 打包前端与主进程；内核 EXE 作为 extraResources 捆绑
- 未签名（D15B）：Windows SmartScreen 提示"仍要运行"；**macOS Gatekeeper 会拦截未签名应用**（需提供 `xattr -cr` 指引或后续公证——D12 跨平台注意）

### 9.3 分发注意

- 杀软误报：Nuitka + torch 原生库易误报 → 提交白名单（火绒/360/Defender）
- ESP-IDF（2~3GB）不进包 → 安装引导（D7A）
- 更新：阶段 2 手动（设置页"检查更新"→ 下载安装包手动升级；阶段 3 自动，D14）

## 12. 验收标准

1. 干净机器：安装包 → 7 天试用或扫码开通（内测优惠 ¥29/半年，标准 ¥59/半年）→ 可运行
2. 界面提交任务 → 流式日志（L1~L4 事件可见操作过程）→ SUCCESS → **最后一条事件为"产物就绪"并附产物路径** → 工作区继续优化 → 导出 zip/bin
3. 中断 → 节点级续跑成功；"从头重跑"可用
4. 4 路并发同时运行不串扰
5. 杀掉内核 → 自动重启 → 任务可续跑
6. 扫码支付后订阅立即生效；到期正确拦截；伪造激活/回调无效
7. LLM 配置界面切换无需重启
8. **任务详情可查 Token 用量（总 token / 按节点分布 / 估算费用）**
9. **应用内可浏览工程源码文件树并查看文件内容（类 Cursor/Qoder 只读体验）**
10. **可回看历史会话（需求→结果卡片），并可从旧会话继续优化**
11. 三平台核心流程可用
12. 内核 EXE 无源码泄露；渲染进程无业务逻辑（代码审查可验证）

## 13. 风险与边界

| 风险 | 影响 | 缓解 |
|---|---|---|
| 在线校验依赖服务端可达（D24） | 本地无公网 → 校验退化 | Cloudflare Tunnel（S3）免费公网暴露；离线缓存容错 |
| Cloudflare Tunnel 稳定性 | Tunnel 抖动 → 校验失败 | 离线缓存宽限 + 重试；可迁移云服务器撤 Tunnel |
| 聚合支付平台风险（D21B） | 平台跑路/风控/手续费 | 选大平台（S2 试用后定）、备用手动发码 |
| Electron 体积与内存 | 安装包 ~150MB+ | 可接受（D20 已定）；asar 压缩 |
| Nuitka × torch 三平台 | 打包失败/体积大 | W1 三平台 PoC；torch 版本锁定 |
| macOS 未签名 | Gatekeeper 拦截 | `xattr -cr` 指引；后续公证 |
| 杀软误报 | 无法安装 | 白名单提交 |
| 4 路并发编译资源压力 | 个人机 CPU/内存 | 并发数可配置（设置页可调 1~4） |
