## 一、项目整体目标

实现垂直嵌入式 Agent，业务流程：**用户产品需求 → 芯片选型 → Datasheet 检索 RAG → 固件代码生成 → GCC 编译 → 编译报错解析 → 自动修复代码 → 输出可运行固件**；暂不接入 PCB 设计能力，后期迭代扩展。
最终产品形态：桌面 EXE 程序，支持收费授权弹窗、防逆向打包、用户可自由切换任意 LLM（DeepSeek/OpenAI/Ollama 本地模型等）。

## 二、技术选型总原则

1. 阶段 1：优先业务闭环验证，极致开发效率，选用 Python + LangGraph；
2. 阶段 2：产品化落地，解决 Python 并发、打包、客户端痛点，采用 Tauri‑TS 网关 + Python 业务内核分层架构；
3. 阶段 3：业务稳定后，性能与分发升级，可选 Go 重构调度层或接入 DeepSeek‑Harness 做顶层运行时。

---

# 阶段 1：MVP 原型验证（0‑1 快速跑通业务闭环）

## 1. 核心目标

不考虑 GUI、打包、并发、授权付费，仅验证核心 Agent 业务流程可行性，快速产出可运行的固件开发逻辑。

## 2. 技术栈

- 业务编排：Python + LangGraph（StateGraph 实现多阶段状态流转）
- RAG 检索：LangChain + 向量库，解析芯片 Datasheet、物料手册、嵌入式开发规范
- 工具调用：Python subprocess 调用 arm‑gcc、openocd，正则解析编译报错日志
- LLM 适配：自研统一适配器，兼容 OpenAI 格式接口，支持 DeepSeek、本地 Ollama 等
- 服务暴露：极简 FastAPI，仅提供任务提交、结果查询接口，不实现 SSE 长连接

## 3. 业务状态机流程设计
用户需求输入
    ↓
芯片选型节点（RAG检索芯片参数、库存、适配开发板）
    ↓
固件代码生成节点（基于选型芯片生成适配开发板的驱动/业务代码）
    ↓
编译执行节点（调用交叉编译器编译工程）
    ↓
错误分类判断
├─ 编译成功 → 输出固件文件，任务结束
└─ 编译失败 → 解析报错类型，分支回退：
   ├─ 语法错误 → 返回代码生成节点修改代码
   ├─ 引脚/芯片配置错误 → 返回芯片选型节点重新匹配
   └─ 环境异常 → 重试编译


## 4. 开发重点

1. 完成 LangGraph 节点定义、条件边跳转、基础重试策略；
2. 完成 Datasheet 文档切片、向量检索、RAG 召回逻辑；
3. 完成编译日志结构化解析，区分不同错误类型；
4. 打通端到端链路：输入需求 → 自动完成选型、写代码、编译、修复。

## 5. 阶段产出

本地可运行的 Python 脚本 / 接口服务，输入产品需求，可自动输出固件代码，验证业务逻辑完整闭环。

## 6. 本阶段规避的问题

暂不处理高并发、SSE 流式、桌面 GUI、EXE 打包、授权加密，所有性能与分发问题后置处理。

# 阶段 2：产品化 V1 版本（封装 EXE 客户端，解决 Python 客户端痛点）

## 1. 核心目标

将原型封装为独立桌面 EXE，实现收费授权、LLM 自定义配置、流式日志展示，规避 Python GIL、并发、打包分发缺陷。

## 2. 架构设计：分层双进程架构

### 上层：Tauri‑TS 网关层（客户端主程序）

- 职责：GUI 界面、收费弹窗、激活码校验、LLM 参数配置面板、SSE 长连接流式推送、任务调度、Python 进程守护、EXE 打包主程序
- 优势：TS 无 GIL，异步 SSE 流式体验优秀，并发连接性能强，Tauri 打包单 EXE，用户无需安装 Python 环境

### 下层：Python 业务内核层（Nuitka 编译为二进制）

- 职责：仅处理核心业务计算，LangGraph 状态机、RAG 检索、编译日志解析、固件生成
- 处理方式：不对外暴露长连接，仅提供本地 HTTP 接口；执行任务时产生的事件日志写入本地队列，由 TS 网关主动轮询获取并推送到前端 UI

## 3. 关键技术实现

1. Python 内核使用 Nuitka 编译为二进制文件，提升逆向破解门槛，避免源码直接泄露；
2. IPC 通信采用本地 HTTP 接口，摒弃复杂管道 IPC，调试可通过浏览器 Network 面板直接查看；
3. 授权校验逻辑放在 TS 层，配合服务端激活码校验，核心授权逻辑不耦合 Python 内核；
4. LLM 配置由用户在 TS 界面填写 api_key、base_url、模型名称，统一转发给 Python 内核调用。

## 4. 功能完善点

1. 增加任务中断、断点续跑基础能力；
2. 增加执行日志实时流式展示、固件文件导出；
3. 增加异常监控，Python 内核崩溃自动重启；
4. 打包为单 EXE 安装包，对外分发。

## 5. 阶段产出

可对外交付的桌面客户端 EXE，具备完整 Agent 能力、付费授权、自定义 LLM 切换。

# 阶段 3：迭代优化与架构升级（业务稳定后性能强化）

## 1. 核心目标

业务流程完全定型，不再频繁修改核心业务逻辑，针对并发性能、分发体积、逆向防护做升级，可选两种升级路线。

## 路线 A：Go 重构调度层（极致性能方案）

### 架构调整

1. Go 作为主程序，实现 Agent 任务调度、状态机持久化、SSE 流式、进程管理、LLM 请求转发，编译为单静态 EXE；
2. Python 仅保留核心文本处理模块：Datasheet 深度解析、编译报错精细化结构化提取，暴露轻量 HTTP 接口供 Go 调用；

### 优势

- Go 原生 goroutine 高并发，内存占用低，静态编译无依赖，分发体积更小；
- 逆向破解难度进一步提升，适合长期商业版本迭代。

### 适用场景

用户量增长，并发访问压力变大，追求极致客户端体验。

## 路线 B：接入 DeepSeek‑Harness 作为顶层运行时

### 架构调整

1. DeepSeek‑Harness 作为顶层 Agent 运行时，接管模型管理、工具调度、全链路中断、轨迹回放、沙箱能力；
2. 原有 Python LangGraph 业务逻辑封装为子 Agent 插件，接入 Harness 框架；

### 优势

复用 Harness 成熟的 Runtime 能力，不用自研调度框架，AbortSignal、并行工具调度、会话快照开箱即用；

### 适用场景

需要增强 Agent 高级能力，如多任务并行、工具权限管控、Web 管理后台。

## 3. 扩展能力开发

1. 新增 PCB 设计相关节点，接入立创 EDA 等 API，完善硬件全流程 Agent；
2. 完善失败分类策略，覆盖更多嵌入式编译、硬件设计异常场景；
3. 优化 RAG 知识库，扩充芯片库、工艺规范、开发板例程文档。

---

# 三、整体权衡与避坑说明

1. 0‑1 阶段严禁直接使用 Go 或 Harness 开发原型，业务逻辑高频变动，Python+LangGraph 开发效率远高于其他方案；
2. 严禁让 Python 直接持有 SSE 长连接给前端，所有长连接、并发链路统一交给 TS/Go 处理，彻底规避 GIL 瓶颈；
3. Python 打包优先使用 Nuitka，禁止使用 pyinstaller，防止源码被轻易反编译；
4. 混合架构（多框架、多语言进程）仅在业务稳定后引入，MVP 阶段保持架构极简，降低调试成本。

# 四、版本迭代时间参考（小团队单人 / 双人开发）

- 阶段 1：1~3 周，完成核心业务闭环验证
- 阶段 2：2~4 周，完成 Tauri 客户端 + 授权 + 打包，产出 V1 商业版
- 阶段 3：根据业务需求，2~6 周完成架构升级与功能扩展
