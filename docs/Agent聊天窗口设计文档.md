## 1. 消息模型（输出内容格式）

### 1.1 内容块类型（ContentBlock）

消息 = 有序内容块列表，渲染层按块类型分卡片/段落渲染：

| 块类型 | 内容 | 渲染形态 |
|---|---|---|
| `text` | markdown 文本（含代码块） | 正文段落，代码语法高亮 |
| `tool-call` | 工具名 + 参数摘要 + 状态（pending/running/success/failed） | **工具调用卡片**（可折叠） |
| `tool-result` | 工具结果摘要 + 详情（JSON/文本） | 工具卡片结果态（成功绿/失败红） |
| `diagnostic` | 校验诊断：level/filePath/range/message/ruleId/fixable | **诊断卡**：错误红/警告黄/信息蓝，可点击跳转文件行 |
| `image` | 截图/原理图（base64 或文件引用） | 图片卡 |
| `notice` | 系统通知（会话结束、权限变更、模式切换） | 居中灰条 |

### 1.2 消息结构

```
Message {
  id: string
  role: "user" | "assistant" | "system"
  turn: number          // 规划层 turn（事件字典对齐）
  blocks: ContentBlock[]
  usage?: { tokens, cost? }   // token 用量（assistant 消息尾部）
  status?: "streaming" | "done" | "failed" | "cancelled"
  ts: number
}
```

### 1.3 渲染规则

- 用户消息：**右对齐**气泡（纯文本/需求）。
- 助手消息：**左对齐**，多 block 纵向排列（文本段落 + 工具卡片组 + 诊断卡）。
- 同一 turn 的连续助手消息合并为一个"助手回合"（turn 边界为一次完整回答）。
- 流式阶段：`status=streaming`，text 块增量追加（打字机效果），工具卡片先显示"执行中"骨架。

## 2. 工具调用链的呈现（核心差异点）

一个 step 内模型连续调用多个工具时，按**模型顺序**渲染为**工具卡片组**（可整体折叠）：

```
┌─ 工具调用链（3/5）────────────────────────────┐
│ ✅ rag_search  查 ESP32-S3 手册   0.8s  [详情▾] │
│ ✅ code_generate 生成 main.c      2.1s  [详情▾] │
│ ⏳ build  ESP-IDF 编译            运行中…       │
└──────────────────────────────────────────────┘
```

- 每个工具卡：状态图标 + 工具名 + 参数摘要（截断）+ 耗时 + 展开详情（JSON 参数/结果，截断 3000 字符）。
- 并行工具：同一卡片组内并排。
- 失败工具：红色，错误摘要直接可见（不藏在详情里）。

## 3. 事件 → UI 映射表（对应 5.2 事件字典）

| 事件 | UI 呈现 |
|---|---|
| `turn/start`（payload `{turn}`，已桥接） | 新建助手回合（含轮次序号） |
| `assistant/chunk`（payload `{delta,turn,step}`，已桥接；text-delta 聚合 24 字符） | text 块流式追加（打字机尾巴） |
| `assistant/message` | 回合定型（含 usage） |
| `tool/call` `tool/result`（payload 含 `callId`，已桥接） | 工具卡片组（见 §2） |
| `skill/catalog` `skill/load` | 技能徽章（🧩 已加载：ESP-IDF 工程规范） |
| `check/start` `check/end` `diagnostic` | 诊断卡 + 编译进度条（check 进行中显示"编译中…"） |
| `node/enter` `node/exit` `node/error`（后置） | 事件时间线（流程执行器启用后） |
| `goal/change` | 任务状态徽章（进行中/完成/失败/暂停） |
| `patch/applied` `patch/rolled_back`（后置） | diff 审阅条目（见 §5） |

## 4. 布局结构（窗口三栏）

```
┌──────────────┬──────────────────────────┬──────────────────────┐
│ 文件树 w-64   │  内容窗 flex-1             │  Agent 聊天 w-80       │
│              │  （源码/产物/diff 审阅）     │  ┌──────────────────┐ │
│              │                          │  │ 消息列表（滚动）     │ │
│              │                          │  │ · 用户气泡（右）     │ │
│              │                          │  │ · 助手回合（左）     │ │
│              │                          │  │ · 工具卡片组        │ │
│              │                          │  │ · 诊断卡            │ │
│              │                          │  ├──────────────────┤ │
│              │                          │  │ 输入框（Ctrl+Enter） │ │
│              │                          │  ├──────────────────┤ │
│              │                          │  │ 状态栏：会话状态·端口│ │
│              │                          │  │ ·权限·模式·token    │ │
│              │                          │  └──────────────────┘ │
├──────────────┴──────────────────────────┴──────────────────────┤
│ 串口监视面板（可折叠抽屉，底部）                                    │
└─────────────────────────────────────────────────────────────────┘
```

- **聊天栏内部**：消息列表（自动跟随滚动，用户上滚时暂停跟随）/ 输入框（Ctrl+Enter 提交）/ 底部状态栏。
- **串口面板**：底部抽屉，MCU 工程自动可用；独立于对话流（不是气泡），显示串口输出 + 发送框 + 端口/波特率。
- 布局可左右对调（沿用现有 `layout` 卡片切换）。

## 5. 产品特有交互

1. **会话确认结束 → 烧录**：对话中出现助手"已就绪，是否烧录？"→ 用户点击烧录按钮 → **弹窗确认端口**（列出可用 COM 口）→ 确认后进入烧录进度（底部状态栏进度条 + 串口面板自动打开）。对话中模型**不能**直接触发烧录（`flash` 工具仅在会话结束后可用，见 V3.2 §0.6/§4.2）。
2. **diff 审阅**：`edit_file` 修改后生成 diff 卡片（`patch/applied` 后置事件），用户批准/拒绝后应用。
3. **诊断跳转**：点击诊断卡 → 内容窗打开对应文件并定位到 range 行（高亮）。
4. **停止**：助手回合右上角"⏹ 停止"按钮 → `cancel` 当前 turn（对应规划层取消机制）。
5. **任务状态**：标题栏/状态栏显示 goal 状态（进行中/完成/失败/暂停）+ 断点续跑入口。

## 6. 数据流（渲染进程零业务逻辑）

```
渲染层（纯展示）
  ├─ onKernelEvent(seq 增量) → 事件 → block 组装（渲染层仅做事件→块映射，不含 Agent 逻辑）
  ├─ getConversation(task_id) → 历史消息（聊天打开时一次性加载，或按 seq 增量补）
  ├─ sendChat(message) → 新 turn
  └─ cancel / confirmFlash(port) → 交互指令
        ↓ IPC（preload 白名单）
主进程（中间人）→ 内核 HTTP（events / chat / cancel / flash 确认）
```

- **block 组装在渲染层**：从事件流还原内容块（`tool/call` → 工具卡，`assistant/chunk` → text 增量……），持久化仍以事件/消息为准（不存渲染态）。
- 现有 2.5s 轮询保留为兜底，`onKernelEvent` 实时事件优先。

## 7. 与当前实现（气泡版 ChatPane）的迁移

| 现状 | 目标 | 改动 |
|---|---|---|
| 事件气泡（左对齐文本） | 助手回合 + 工具卡片组 + 诊断卡 | 重写 ChatPane 渲染模型 |
| 事件时间线 `<details>` 折叠 | 工具卡片组（三态） | 替换 |
| 产物悬浮列表 | 产物卡片（点击内容窗打开） | 保留增强 |
| 2.5s 轮询 | 轮询兜底 + 实时事件优先 | 保留 |
| — | 串口监视抽屉 / 烧录确认 / diff 审阅 / 诊断跳转 | 新增 |

## 8. 分阶段落地

> **编号与时间顺序**：W4（M3 · 2026 阶段3 桌面 UI 接点补完）已在气泡版 ChatPane 上先行落地
> （见《阶段3-DSH能力等价启用排期.md》§13 附录 I / 当前 ChatPane.tsx）；W1–W3 是其后在
> block 渲染模型上的重写分阶段，**未排入本阶段（2026 阶段3）**，按排期独立估期。下表按
> 新渲染模型的落地顺序编号，不代表 W1–W3 先于 W4 执行；落地次序 = W4 → W1 → W2 → W3。

- **W1（block 基础）**：消息模型 + 文本/tool-call/tool-result 卡片 + 流式渲染 + 工具卡片组三态；替换气泡模型。
- **W2（校验闭环 UI）**：diagnostic 卡 + 编译进度 + 诊断点击跳转；skill 徽章。
- **W3（产品交互）**：会话结束烧录确认弹窗 + 串口监视抽屉 + diff 审阅（patch 事件后置时联动）。
- **W4（M3 · 桌面 UI 接点补完，2026 阶段3）**：审批/plan 弹窗（approval/questions 轮询应答，
  §阶段3 排期 §13 附录 I）、plan-mode 意图开关（ChatPane 会话 + HomeView 新会话预设）、
  git 会话状态条与显式回滚（gitStatus/gitRollback，破坏性二次确认）、既有烧录弹窗保留。
  ChatPane 渲染仍为气泡+事件流形态（W1 block 模型重写未排入本阶段，见 §13 附录 I.4 边界）。

## 9. 验收标准

> 验收 1–4 为 block 模型**目标态**验收（在 W1–W3 重写完成后生效）；验收 5 为 **M3（2026 阶段3）**
> 在气泡版 ChatPane 上的补充验收，已于 W4 接点落地（见 §阶段3 排期 §13 附录 I）。

1. 多工具调用的对话能按"助手回合 + 工具卡片组"清晰回放，卡片三态（执行中/成功/失败）正确。
2. 编译校验产出诊断卡，点击可跳转文件行号。
3. 会话确认结束后才出现烧录入口，烧录前必须弹窗确认端口。
4. 渲染进程无 Agent/LLM/编译业务逻辑（沿用 D19 铁律）。
5. **（M3 补充）** Agent 运行/空闲均可收到审批与 plan 审阅弹窗，应答后会话续跑；
   git 仓库会话显示状态条（repo/head/dirty），回滚需二次确认；
   plan-mode 可在新建会话前或会话中切换，下一条消息按计划模式执行。
