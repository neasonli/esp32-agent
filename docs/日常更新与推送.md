# 日常更新与推送（改完代码怎么传到 GitHub）

> 适用对象：你自己以后每次改完 LCode 想同步到 GitHub 时看这一页。
> 两个仓库：`neasonli/lcode`（开源，公开）、`neasonli/lcode-kb`（知识库，永久私有）。

## 0. 一分钟版

**公开仓（绝大多数改动都走这条）**——在仓库根目录跑一条命令：

```powershell
cd D:\1_ai_project\mcu_ai_agent
powershell -ExecutionPolicy Bypass -File tools\publish-public.ps1 -Message "feat: 你这次改了什么"
```

它会依次做：导出干净副本 → 独立审计 → 显示改了哪些文件 → 提交 → 推送。
任何一步不过就停下并告诉你原因，**不会把有问题的东西推上去**。

想先看看会发生什么（不提交不推送）：

```powershell
powershell -ExecutionPolicy Bypass -File tools\publish-public.ps1 -DryRun
```

**私有知识库仓（改了 `lcode-kb` 里的代码才需要）**：

```powershell
cd D:\1_ai_project\lcode-kb
git add -A
git commit -m "你改了什么"
git push origin main
```

## 1. 先搞清一件事：**别在导出目录里改文件**

```
D:\1_ai_project\mcu_ai_agent\        ← 源（你改代码只改这里）
        │  tools\make-public-export.ps1  （白名单拷贝 + 安全扫描）
        ▼
D:\1_ai_project\lcode-public-export\ ← 生成的镜像（只有它连着 GitHub）
```

`lcode-public-export` 里的内容**每次导出都会被重新生成**（脚本会清空重拷，只保留 `.git`）。
在那里手改的东西下次导出就没了。**要改代码就改 `mcu_ai_agent` 里的那份。**

导出目录里唯一"活"的东西是 `.git` —— 你的提交历史在这里，脚本已经会保护它（早期版本会把它删掉，已修）。

## 2. 公开仓：日常更新（推荐用脚本）

### 2.1 一条命令

```powershell
cd D:\1_ai_project\mcu_ai_agent
powershell -ExecutionPolicy Bypass -File tools\publish-public.ps1 -Message "fix: 设置页保存后规划器不重启的问题"
```

输出长这样（每步都能看懂）：

```
==> 1/5 exporting the public tree (whitelist + secret scan)
  files: 154   size: 1.57 MB
  OK: no .env, private keys, vendor PDFs, third-party app dumps or hardcoded API keys.
    [ok] export finished
==> 2/5 independent audit (second opinion)
    VERDICT: PASS（无硬命中；提示项请人工确认）
    [ok] audit PASS
==> 3/5 what changed
      M  lcode/desktop/src/main/index.ts
    [ok] 1 path(s) changed
==> 4/5 commit
    message: fix: 设置页保存后规划器不重启的问题
    [ok] committed 3a1b2c4
==> 5/5 push to neasonli/lcode
    [ok] pushed 3a1b2c4 -> https://github.com/neasonli/lcode
```

常用开关：

| 开关 | 用途 |
|---|---|
| `-Message "..."` | 提交说明（不填会自动生成 `chore: sync workspace changes (时间)`） |
| `-DryRun` | 只做导出 + 审计 + 列出改动，**不提交不推送** |
| `-NoPush` | 提交到本地，先不推（想再检查一遍时用） |
| `-SkipAudit` | 跳过独立审计（**不建议**） |

### 2.2 它内部到底做了什么（想看/想手敲时）

```powershell
# ① 导出（白名单拷贝 + 安全扫描；有命中直接 exit 1）
cd D:\1_ai_project\mcu_ai_agent
powershell -ExecutionPolicy Bypass -File tools\make-public-export.ps1

# ② 独立审计（另一套实现的第二双眼睛）
python tools\audit-public-export.py

# ③ 提交 + 推送
cd D:\1_ai_project\lcode-public-export
git status                     # 看一眼都是什么改动
git add -A
git commit -m "feat: xxx"
git push origin main
```

## 3. 私有知识库仓（`lcode-kb`）

它**不经过导出**，直接就是源目录：

```powershell
cd D:\1_ai_project\lcode-kb
git status
git add -A
git commit -m "fix: 检索时按 chip 过滤的边界"
git push origin main
```

**发一个新版本的 wheel**（授权用户要拿包时才需要）：

```powershell
# 先改 pyproject.toml 里的 version，再：
powershell -ExecutionPolicy Bypass -File D:\1_ai_project\mcu_ai_agent\tools\publish-kb-wheel.ps1 -Repo neasonli/lcode-kb
```

它会：构建 sdist + wheel → 检查 wheel 里没有语料/向量库/密钥 → 打 tag `kb-v<版本>` → **先推 tag 再建 Release**（顺序很重要，先建 Release 会拿到 GitHub 的 HTTP 500）→ 上传附件。

- 向量库（`data/rag_store/`）**永远不会**进 wheel、进 git、进 Release —— 脚本会拒绝。要单独给授权用户就在同一个 Release 里手动传 `kb-store-<版本>.zip`。
- 想先看计划：加 `-DryRun`。

## 4. 网络问题（这台机器特有，已配好一次）

这台机器**到 `github.com:443` 是被墙的**（时通时不通），所以 HTTPS 推送会报
`Failed to connect to github.com port 443: Timed out`。

已经写进 `C:\Users\F\.ssh\config`，把 `github.com` 映射到能通的 `ssh.github.com:443`：

```
Host github.com
  HostName ssh.github.com
  Port 443
  User git
  IdentitiesOnly yes
  IdentityFile ~/.ssh/id_rsa
```

自检（应输出 `Hi neasonli! You've successfully authenticated...`）：

```powershell
ssh -T git@github.com
```

- 以后再新建的仓库也用 `git@github.com:owner/name.git` 这种 SSH 地址，就自动走 443。
- 如果哪天 `ssh -T` 也不通，先试代理/VPN；`api.github.com` 和 `uploads.github.com` 通常是通的（我这边的 API 操作就是走它们）。

## 5. 发版（可选，目前还没发过）

公开仓的 CI（`.github/workflows/build-installers.yml`）**只在推 tag 时**才构建并发布安装包：

```powershell
cd D:\1_ai_project\lcode-public-export
git tag v0.1.0
git push origin v0.1.0        # 三平台构建 → 自动挂到该 tag 的 Release
```

⚠️ 注意两点：
1. CI 构建的是**不带 ESP-IDF 的 base 版**；带 IDF 的 `-full` 版体积 141 MB + 742 MB 载荷，要**本地**出（`tools\build-installer.ps1 -Variant full`）再用 `tools\publish-release.ps1` 挂在**本机**的 Release 上。
2. **安装包永远不要提交进 git**（GitHub 单文件上限 100 MB），只走 Release 附件。

## 6. 常见情况对照表

| 现象 | 原因 / 怎么办 |
|---|---|
| `Failed to connect to github.com port 443` | 见 §4；SSH 通道已配好，用 SSH 地址推送 |
| 脚本说 `audit found hard hits` | 看它列出的文件与规则。**不要**加 `-SkipAudit` 蒙过去；那通常是 `.env`/密钥/向量库/大文件漏进了导出范围 |
| `make-public-export` 报 `PRIVATE SUBTREE LEAKED` | 导出脚本的硬断言：私有子树（如 `lcode/server`、载荷目录）不应出现。检查是否误改了白名单/排除规则 |
| 导出后改动比预期多 | 正常：导出是**整棵树重新生成**，所以你在工作区删掉的文件也会在导出目录里被删（提交时会体现为删除） |
| 手滑在 `lcode-public-export` 里改了文件 | 下次导出会被覆盖。正确做法是改 `mcu_ai_agent` 里的源，再跑脚本 |
| `EBUSY ... icudtl.dat`（装 Electron 时） | 有 LCode 实例在跑，先关掉窗口 |
| 提交里出现了 `dist/`、`*.exe`、`kb-payload.zip` | 不该发生（`.gitignore` + 导出规则都排除了）。若真出现，**别推**，先删掉再提交 |
| 想撤销上一次提交（还没推） | `git reset --soft HEAD~1`（保留改动）；已经推了就 `git revert <sha>`，别 force push |
